## 第 0 阶段验证

### 已通过的契约

- 参考配置的 Reynolds 数为 `0.002`，与文档一致。
- 物理、传感和控制周期分别为 `0.01 s`、`0.1 s`、`0.2 s`，参考运行报告 200 个物理步、含初始时刻的 21 次测温和 10 次控制更新。
- 同一配置及传感器种子重复构造传感器时，测温序列逐值一致。
- 改变传感器种子会改变测量序列，不改变真值温度和 Reynolds 数。
- `SensorReading` 只有两个字段：`temperature_K`、`sample_time_s`。配置若显式加入 `true_gradient_K_per_m` 会被拒绝。
- 线性温度场对连续坐标直接求值，没有沿用旧平台的整数栅格取整。
- 参考场的舒适温度位于 `x=0.015 m`；在其左右各 `0.002 m` 的温度为 `293.05 K` 和 `293.25 K`，相对 `293.15 K` 对称。
- 结果包包含解析配置、清单和结果；结果被明确标记为 `scientific_result: false`。

### 已发现并修复 V0-1：终止时刻之外仍可能采样

`run_phase0_probe()` 用 `round(duration / sensor_dt) + 1` 计算样本数。构造一个仍满足当前配置校验的反例：

```text
physics_dt_s = 0.01
sensor_dt_s  = 0.10
duration_s   = 2.06
```

实际结果为：

```text
last sample time = 2.10 s
duration         = 2.06 s
clock_counts     = {physics_steps: 206,
                    sensor_samples_including_t0: 22,
                    control_updates: 10}
```

最后一次样本超出实验时窗。控制更新也使用 `round()`，会在半周期附近出现银行家舍入造成的含混。正式仿真应由明确的离散事件时刻生成计数，例如只保留满足 `t <= duration` 的事件，并明确终点是否包含；不能由四舍五入推断事件数。

影响：若第 1 阶段沿用这套计数，首次到达、驻留比例、样本数量和噪声平均都可能纳入终止时刻之外的数据。当前 `TimeConfig` 已要求 `duration_s` 同时为物理、传感和控制周期的整数倍，上述输入会以 `ValueError` 拒绝；参考计数没有越界事件。

### 已发现并修复 V0-2：配置中的未知字段和小数整数被静默处理

在参考配置中加入以下字段：

```json
{
  "unexpected_model_parameter": 123,
  "sensor": {"noise_st_K": 99}
}
```

解析仍成功，所得 `ExperimentConfig` 与原配置相等，配置 SHA-256 也完全相同。也就是说，参数名拼错后，结果包既不报错，也不保留这项输入。

此外，本次反例确认以下输入均会静默通过：

```text
schema_version = 1.9  -> 1
domain.dimension = 2.9 -> 2
seeds.sensor = 202.9 -> 202
```

影响：正式参数扫描可能误以为某参数已改变，实际运行和摘要却使用旧值；这会破坏配置即实验定义的可审计性。当前第 0、1 阶段在顶层和每个嵌套对象中都精确校验字段，整数域拒绝布尔值与非整数数值；上述反例均以 `ValueError` 拒绝。

### 非阻断限制

- 第 0 阶段只真正使用传感器随机源；第 1 阶段已验证传感与控制随机流隔离。当前线性场是确定性的，`environment` 种子没有实际随机对象可驱动；引入随机温度场时需新增相应隔离测试。
- `LocalTemperatureSensor.sample()` 接受任意调用时间，本身不执行采样时钟约束。时钟职责可以放在仿真器，但必须有集成测试证明物理步长变细不会增加独立测温次数。
- 结果目录由配置摘要命名；相同配置重复运行会覆盖同目录的三个 JSON 文件，其中清单时间会变化。单次结果没有丢失科学数组，但批量重复实验若需要保留每次运行，应另设运行实例标识或明确允许覆盖。
- Python 标准库的伪随机实现用于当前探针是可复现的，清单也记录 Python 版本；跨 Python 实现的逐值一致性未作保证。

## 第 1 阶段独立性质验证

### 机制与观测权限

控制器实现只在 `observe(SensorReading)` 中接触 `temperature_K` 和 `sample_time_s`。它内部持有预先给定的 `T*`，以 `|z-T*|` 形成测得的温度误差，再用快、慢两个指数记忆判断误差是在改善还是恶化。它没有位置、方向、真值温度、梯度或温度场对象。

构造相同误差幅值的冷热读数时，控制状态逐值相同。分别构造明确改善和恶化的序列，转向率从下限 `0.01 s⁻¹` 变到上限 `0.5 s⁻¹`，方向符合“改善时延长持续运动、恶化时增加反向机会”的假设。快、慢时间常数被 schema 约束为 `τ_fast < τ_slow`；相等时间尺度的退化情形不作为正式配置，但零响应增益提供了不利用趋势的基准。

轨迹现已同时记录 `measured_temperature_K`、该读数实际的 `measured_sample_time_s` 和当前步是否发生新采样的 `sensor_sampled`，不会把采样间隔内保持的旧读数误记成当前时刻的新测量。

### 时钟与数值收敛

把物理步长从 `0.01 s` 减到 `0.005 s`，保持总时长、传感和控制周期不变，结果为：

| 量 | `dt=0.01 s` | `dt=0.005 s` | 差异 |
|---|---:|---:|---:|
| 物理步 | 18,000 | 36,000 | 预期翻倍 |
| 含 `t=0` 的测温次数 | 1,801 | 1,801 | 0 |
| 控制更新次数 | 900 | 900 | 0 |
| 共同采样时刻的位置 | — | — | 最大 `6.32×10⁻15 m` |
| 舒适区驻留比例 | — | — | `8.18×10⁻14` |
| RMS 温度误差 | — | — | `7.77×10⁻16 K` |

传感与控制事件没有随物理网格加密而增加，运动轨迹和三个真值指标都在机器精度附近一致。RMS 温度误差最终改为在每个反射匀速分段上解析积分线性温度误差的平方，不再依赖物理步端点求积。进入身体模型后运动不再是分段匀速解析轨迹，仍需重新做步长收敛检查。

### 随机源隔离

- 在 `response_gain=0` 时只改变传感器种子，测量序列改变，位置与方向序列逐值不变。
- 只改变控制器种子时轨迹改变；在各传感事件上提取 `measured_temperature_K - true_temperature_K`，两次运行的噪声残差流最大差为 `0 K`。
- 相同配置重复运行的完整结果逐值一致。
- 当前确定性线性场没有使用环境随机种子；这属于尚未启用的接口，不是已经验证的随机环境隔离。

### 镜像对称与冷热两侧

把温度场、初始位置和初始方向关于区域中点镜像，保持噪声及控制随机流相同。最终结果为：

```text
最大镜像位置误差       1.40e-14 m
最大真值温度差         1.42e-12 K
最大测量温度差         1.42e-12 K
每一步方向均互为反向   true
转向次数               两侧均为 13
```

首次进入时间、驻留比例和 RMS 误差的镜像差分别约为 `6.3×10⁻11 s`、`3.3×10⁻13` 和 `2.7×10⁻13 K`，属于浮点误差。舒适边界加入数值容差后，不再被该误差放大成整整一个物理步的差异。

另做了每侧 32 条轨迹的小样本检查。它用于发现方向性错误，不作为最终统计结论：

| 起点与模型 | 到达率 | 平均驻留比例 | 平均 RMS 误差 / K | 成功者平均首次进入 / s |
|---|---:|---:|---:|---:|
| 冷侧，趋势响应 | 1.0000 | 0.5459 | 0.54462 | 68.80 |
| 热侧，趋势响应 | 0.9688 | 0.5380 | 0.55579 | 65.49 |
| 冷侧，零响应 | 0.3438 | 0.0608 | 0.97845 | 100.48 |
| 热侧，零响应 | 0.1562 | 0.0293 | 1.12166 | 123.10 |

趋势响应在冷热两侧都明显优于本轮零响应样本，说明代码没有退化成单向追逐高温。冷热两侧的有限样本差异还不能解释为物理不对称；正式实验需要增加样本量、置信区间以及镜像配对设计。

### 指标与边界反例

- 初态位于舒适温度且速度近零时，`first_entry_time_s=0`、驻留比例为 `1.0`。
- 短时运行未到达时，`entered_comfort_region=false` 且 `first_entry_time_s=null`。这正确保留了右删失信息；后续群体汇总仍需采用到达率/生存分析，不能只平均成功轨迹。
- 首次进入、驻留比例和 RMS 温度误差均使用真值温度，含噪读数只进入控制器。
- 构造单个物理步跨越整个舒适带、终点仍在带外的反例后，当前实现会沿反射前后的匀速线段求与舒适带的交集，并插值得到首次进入 `0.019 s`，不会再漏报事件。
- 反射运动保留每段路径用于事件积分；参考范围内边界、方向与温度镜像均通过。

### 非阻断限制

- 32 条/侧只足以做实现级反例检查。正式参数扫描尚需预注册样本数或精度准则、置信区间、右删失处理，以及独立重复。
- 参考控制器在明显改善/恶化时容易达到转向率上下限。后续扫描应报告饱和比例，避免把不同响应增益误认为仍处在线性响应区。
- 当前只有独立高斯测量噪声；相关噪声、采样积分时间和带宽尚未实现。
- 单轨迹结果标记为 `scientific_result: true`，表示它属于科学模型输出，不代表单条轨迹已经支持趋温机制结论。正式报告应引用群体统计和对照。
- 参考模型完成了数值机制，没有完成计划中的弱响应解析推导、漂移/扩散估计及噪声—记忆参数图。

## 第 1 阶段配对集合独立验证（2026-09-28）

本轮只验收 `phase1_paired_ensemble` 的实现与结果包，不把有限样本结果提升为科学结论。独立探针保存在 `/private/tmp/phase1_ensemble_probe.py`，使用参考配置复算 API、文件结果包和真实命令行入口。

### 配对、种子与对照条件

- `replicates` 在 Python API 中严格拒绝布尔值、零、负数、浮点数、字符串和 `None`；CLI 对 `0` 和 `1.5` 均返回非零状态并报告必须为正整数。
- 第 `i` 个重复使用 `sensor=202+i`、`initial_state=303+i`、`controller=404+i`。每一对的响应组与零响应组逐字段比较后，三项种子完全相同，配置的唯一差异是对照组 `response_gain_per_K_s=0`。
- `environment` 种子在各重复中保持 `101`。当前温度场完全确定且不读取该种子，因此这不会降低当前配对样本的独立性；一旦加入随机温度场，集合生成器必须明确把环境种子纳入跨重复方案并新增隔离测试。
- 两组都以 `record_trajectory=False` 调用单轨迹实验；对汇总对象进行递归检查，任何层级都不含 `trajectory`。

### 统计定义复算

使用人工构造的“已到达、未到达、到达时间超过观察窗”混合记录，独立复算得到：

- 条件平均首次到达时间只使用 `entered_comfort_region=true` 的记录；全组无人到达时为 `null`。
- 限制平均首次到达时间逐条使用 `min(first_entry_time_s, duration_s)`，未到达记录贡献完整 `duration_s`。三条人工响应记录 `[10 s, 未到达, 250 s]` 在 `duration=180 s` 时得到 `123.333333 s`，与实现逐值一致。
- 到达数、到达率、驻留比例均值、RMS 温度误差均值和转向数均值，都能从 `paired_replicates` 的逐条指标重新计算并逐值匹配组汇总。

### 结果包、命令行与可复现性

- 相同配置与 `40` 个重复连续运行两次，完整科学汇总对象逐值相等。
- 直接调用 `write_phase1_ensemble_bundle(..., replicates=4)` 与实际子进程执行 `python -m thermotaxis phase1-ensemble ... --replicates 4` 所得 `summary.json` 逐值相等。
- 结果目录严格包含 `config.resolved.json`、`manifest.json` 和 `summary.json`；JSON 规范化后的 resolved config 与输入配置逐值相同，汇总不含完整轨迹。
- 配置摘要没有把 `replicates` 编入 SHA-256，但目录名、清单和汇总都显式记录重复数，因此不同重复数不会写入同一目录。相同配置与重复数再次运行会覆盖同一路径；这沿用当前结果包的覆盖语义。
